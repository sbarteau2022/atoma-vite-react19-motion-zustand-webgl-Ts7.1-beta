# Website audit — October 28, 2026

## Scope and design

Audit of GitHub main at 2e20e8a, Pages Functions, D1 migrations, release CI,
account/email, research, public AI and existing browser coverage. Implementation
follows DESIGN.md, including the October 28 API hardening specification.
The requested DOCUMENTATION STANDARDS.MD was not found beneath Desktop/OPS_BOARD;
this report follows the existing repository documentation structure.

## Findings and fixes

- Unknown POST paths previously wrote rate-limit rows keyed by attacker-chosen
  paths and scheduled three cleanup queries. Fixed: resolve a finite route and
  method table before reading bindings. Unsupported methods return 405/Allow.
- Content-Type used substring matching, accepting lookalikes such as
  application/json-evil. Fixed: exact case-insensitive media type with optional
  parameters. Existing streaming 16 KB body enforcement remains intact.
- Release smoke previously accepted any HTTP 200, including HTML fallback or
  missing AI configuration. Fixed: assert JSON and all health flags, a nonempty
  research catalog, and configured account mail. No real mail is sent by CI.
- No open GitHub issues were returned at audit time. This does not establish
  absence of defects; the findings above came from source review.

## Adversarial review and validation

Reviewed parameterized SQL, same-origin writes, bounded request parsing,
password/session hashing, atomic reset consumption, login/reset races,
anonymous AI/email budgets and provider-error redaction. Regression cases cover
50 arbitrary paths without bindings, unsupported methods, deceptive media types,
HTML fallback, failed health HTTP, absent AI, empty catalog and disabled mail.
Existing suites cover forged/expired credentials, token replay/concurrency,
SQL input, oversized/invalid JSON, cross-user bookmarks and provider failures.
Browser coverage includes desktop/mobile layouts, reduced-motion/WebGL fallback,
public routes, AI widget, recovery/verification and company pages. Browser API
mocks do not prove production inference or email delivery.

## UI depth proposal — pending design review

Keep the obsidian/titanium identity and make the central IDE behave coherently:
resizable explorer/editor/inspector panes, keyboard command palette, useful
file tabs, integrated diff/log views, richer empty/loading/error states and
consistent context when moving between work, research and runs. At narrow
widths, use focused pane navigation instead of compressing three columns.
Clearly label simulated execution and telemetry. Define interaction states in
DESIGN.md before implementation, then validate keyboard use, 320–1440px
layouts, reduced motion and performance. The lazy Three.js chunk remains large;
measure actual loading/render costs before adding visual effects.

Pin this interaction design before connecting Kimi or external tool execution.
The present AI remains a bounded public guide with no tool access. This audit
introduces no visual redesign, model change, new data collection or migrations.
